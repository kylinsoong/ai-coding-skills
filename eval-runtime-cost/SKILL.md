# 运行成本打分技能

读取用户指定的运行成本 CSV,按下列固定规则打分,输出评分 CSV。打分规则（列结构、权重、归一化）是本技能方法论，固定不变；CSV 数据本身是参数。

## 输入

`$ARGUMENTS` 依次为(空格分隔):

1. **输入 CSV 路径**(必填):运行成本数据,列结构见下
2. **输出 CSV 路径**(可选):缺省为输入 CSV 同目录下的 `runtime-cost-score.csv`

缺省时查找当前目录下 `runtime-cost.csv` 并提示用户确认路径。

## 评分规则(以本文件为准,不要自创量尺)

CSV 列:模型,时间(分钟),对话次数,会话次数,模型调用次数,Token 消耗(万),金额消耗(元),一次执行完成,执行集成测试

总分 10 分,权重分配:

| 维度 | 权重 | 打分方式 |
|---|---:|---|
| 一次执行完成 | 2 | 是 = 2,否 = 0.5(固定档,不归一化) |
| 金额消耗(元) | 2 | 定量列归一化(见下) |
| 执行集成测试 | 1 | 是 = 1,否 = 0(固定档) |
| 时间(分钟) | 1 | 定量列归一化 |
| 对话次数 | 1 | 定量列归一化 |
| 会话次数 | 1 | 定量列归一化 |
| 模型调用次数 | 1 | 定量列归一化 |
| Token 消耗(万) | 1 | 定量列归一化 |

### 定量列归一化公式

对每个定量列,在**参与对比的全部模型**内取 min/max:

```
归一化得分 = 10% + 90% × (max − 该模型值) / (max − min)
```

即列内最便宜(最小值)得满权重分,最贵(最大值)保底权重 × 10%。列内所有值相同时全列得满权重分。所有定量列都是越低越好。

### 定性列

- 一次执行完成:是 = 2 分,否 = 0.5 分。
- 执行集成测试:是 = 1 分,否 = 0 分。

## 计算与输出

```
模型总分 = Σ(定量列权重 × 该列归一化得分) + 一次执行完成得分 + 执行集成测试得分
```

调用内置脚本 `scripts/score_runtime_cost.py` 计算(用 python3 执行,不要手算):

```bash
python3 scripts/score_runtime_cost.py <输入CSV> [输出CSV]
```

脚本行为:

- 跳过空行(`模型` 为空的行)。
- 输出按总分**降序**排列。
- 打分粒度保留两位小数。

输出 CSV 列结构:

```
模型,时间得分,对话得分,会话得分,调用得分,Token得分,金额得分,一次执行完成得分,执行集成测试得分,总分
```

各定量列输出的是**该维度的实际得分(权重 × 归一化后,即上表权重尺度)**,总分 = 各列之和,四舍五入两位小数。

## 校验(写文件前必做,脚本内置)

1. 每个定量列得分范围 ∈ [权重×0.1, 权重×1.0],越界即算错。
2. 每行:各列得分之和 = 总分(容差 0.01)。
3. 权重合计 = 2+2+1+1+1+1+1+1 = 10,总分上限 10。

校验不过脚本以非零退出码失败,修脚本重跑,不得手工改数。

## 已知局限(输出时不修数,但结论里要提)

- min-max 归一化对极值敏感:单项最贵的模型该维度被压到 10% 保底,是**相对分**,读作"该维度全场垫底",不代表绝对不可用。
- 对话次数与会话次数在本数据中通常相同,实际重复计入了 2 分权重,是有意设计(返工信号加权),不是 bug。
